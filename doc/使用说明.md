# rs485-test 使用说明

QCM6125 上的 RS485 半双工测试程序。空闲拉高 GPIO 接收，发送时拉低，发完再拉高。

默认：`/dev/ttyHS3`、GPIO123、115200、`N8N1`。需要 **root**。

更完整的需求与验收见 [PRD.md](PRD.md)。

## 1. 准备

### 1.1 主机交叉编译

在 x86_64 Linux（可联网）上：

```bash
./scripts/compile.sh
```

脚本会：

1. 若无 rustup，则安装到用户目录。
2. 若 `tools/` 下没有 aarch64 musl gcc，则下载 Bootlin 工具链。
3. `cargo build --release --target aarch64-unknown-linux-musl`。
4. 拷贝到 `dist/rs485-test`。

手动放置工具链：把 aarch64 musl 交叉编译目录放到 `tools/`，保证能找到 `*/bin/aarch64-linux-gcc` 或 `aarch64-*-linux-musl-gcc`。

### 1.2 拷到目标板

至少拷贝：

- `dist/rs485-test`
- `scripts/start.sh`
- `scripts/stop.sh`

三者放在同一目录最省事，例如 `/opt/rs485/`。也支持二进制在 `../dist/` 或当前目录。

```bash
chmod +x rs485-test start.sh stop.sh
```

### 1.3 权限与设备

```bash
ls -l /dev/ttyHS3
ls /sys/class/gpio/export
```

必须能打开串口、能 export GPIO。直接 root 运行即可。

## 2. 命令行总览

```text
rs485-test [全局选项] [子命令]
```

不写子命令 = `duplex`。

### 2.1 全局选项

| 选项 | 默认 | 含义 |
|------|------|------|
| `-d, --device` | `/dev/ttyHS3` | 串口设备 |
| `-b, --baud` | `115200` | 波特率 |
| `--format` | `N8N1` | uarttest 风格：`N8N1` 或 `115200N8N1` |
| `-g, --gpio` | `123` | 方向脚。1=RX，0=TX |
| `--tx-setup-us` | 1 字节时间，下限 50 µs | 拉低之后、写串口之前的等待。省略则按波特率/帧格式计算 |
| `--tx-hold-us` | 2 字节时间，下限 50 µs | `tcdrain` 之后、拉高之前的等待。省略则按波特率/帧格式计算 |
| `--frame-idle-ms` | `30` | 空闲多久算一帧结束（读超时） |
| `-q, --quiet` | 关 | 不打印报文，只打统计 |
| `--crc` | 关 | 按测试帧做 CRC / 序号统计 |
| `--stats-interval-ms` | `1000` | quiet 时统计打印间隔；`0` 表示每包都打 |

`--format` 四字符：校验 `N/O/E`、数据位 `5-8`、流控 `Y/N`、停止位 `1/2`。不支持 `S`。

查看帮助：

```bash
./rs485-test --help
./rs485-test traffic --help
./rs485-test file-send --help
./rs485-test file-recv --help
```

### 2.2 子命令

| 命令 | 作用 |
|------|------|
| `duplex` | stdin 每行发给对端，串口来包打印 |
| `echo` | 收到一帧原样回发 |
| `send <文本>` / `send --file 路径` | 发一次；可加 `--stay` 继续收 |
| `recv` | 只收 |
| `traffic` | 连续发带序号和 CRC 的测试帧 |
| `reverse`（别名 `test`） | 首帧 1～8 字节倒序回发并缓存；之后只比对；6s 无接收则补发缓存 |
| `file-send --file 路径` | 循环分片发文件，等对端 ACK；参数见 [2.3](#23-file-send-参数) |
| `file-recv` | 循环收文件：出错续收、原样落盘；第一份收齐保留；参数见 [2.4](#24-file-recv-参数) |

全局选项对所有子命令生效。`file-send` / `file-recv` 自身的参数如下。

### 2.3 file-send 参数

```text
rs485-test [全局选项] file-send --file <路径> [--md5 HEX] [--count N] [--chunk N] [--interval-ms N] [--ack-timeout-ms N]
```

| 选项 | 默认 | 含义 |
|------|------|------|
| `--file` | 必填 | 源文件路径。空文件拒绝。启动时算一次 MD5 写入 META；每轮按该路径重读分片 |
| `--md5` | 空 | 32 位 hex。给出则必须与启动时本地计算结果一致，否则直接退出 |
| `--count` | `0` | 发送轮数。`0` 表示直到 Ctrl-C |
| `--chunk` | `1024` | 每片数据字节，范围 `1..=8173`（受单帧 8192 上限约束） |
| `--interval-ms` | `20` | META 与各 DATA 片之间的间隔 |
| `--ack-timeout-ms` | `15000` | 一轮发完后等待匹配 `xfer_id` 的 ACK。超时只记统计，继续下一轮 |

`start.sh` 对应：`FILE`（必填）、`MD5`、`COUNT`、`CHUNK`、`INTERVAL_MS`、`ACK_TIMEOUT_MS`。

### 2.4 file-recv 参数

```text
rs485-test [全局选项] file-recv [--dir 目录] [--expect-md5 HEX] [--idle-timeout-ms N] [--max-fail-keep N]
```

| 选项 | 默认 | 含义 |
|------|------|------|
| `--dir` | `/tmp/rs485-rx` | 落盘目录，不存在则创建。应指向真实块设备；若是 tmpfs（常见于 `/tmp`），剔除页缓存可能无效 |
| `--expect-md5` | 空 | 32 位 hex。给出则**每一轮**必须匹配，不再自动记基准，通过也不留 `first-*`。省略则以第一份**收齐**的文件为进程内基准并保留 `first-xfer{id}.bin` |
| `--idle-timeout-ms` | `5000` | 进行中的传输超过该空闲未收到下一片，本轮失败并保留 |
| `--max-fail-keep` | `16` | 目录内 `fail-*` 最多保留份数，超出删除最旧的；**不删除** `first-*` |

收齐后会 `fsync`，对该文件 `posix_fadvise(DONTNEED)`，再重新打开算 MD5。缺片、乱序、重复、坏帧**不中止本轮**，按片号把实际收到的字节写入（不补 0，同一片只留第一次）。未传 `--expect-md5` 时，第一份收齐且通过的文件改名为 `first-xfer{id}.bin` 永久保留；之后相同内容删除 `recv-{id}.part`。失败则改名为 `fail-xfer{id}-got{md5前8位}.bin`，无法解析的坏帧原文为 `fail-xfer{id}-bad.bin`。半截、超时不记基准。Ctrl-C 丢掉未完成的 `.part`，不记失败。ACK 发送失败只打日志，进程继续。

本轮在「全部片到齐 / 空闲超时 / 中途新 META」时结束并回 ACK。缺片时会等到空闲超时，以便乱序迟到的片仍能写入。

| 场景 | 本轮 | 进程 | 落盘 |
|------|------|------|------|
| 缺片 / 乱序 / 重复 / 片长不符 / 坏帧 | 继续收，打「出错…继续收本轮」 | 继续 | 原样写入；坏帧进 `-bad.bin` |
| 全部片到齐且 MD5 通过（第一份、无 `--expect-md5`） | 结束，ACK 成功 | 继续 | 保留 `first-xfer{id}.bin` |
| 之后相同内容通过 | 结束，ACK 成功 | 继续 | 删除本轮 `.part` |
| 未收齐（超时 / 新 META）或 MD5 失败 | 结束，ACK 失败 | 继续 | `fail-xfer*` |
| ACK 发送失败 | 已结束 | 继续 | 已按上表保留 |
| 串口读致命错误 | — | 退出 | — |
| Ctrl-C / `stop.sh` | 丢弃未完成 | 退出 | 不留 `.part`，不记失败 |

`start.sh` 对应：`DIR`、`EXPECT_MD5`、`IDLE_TIMEOUT_MS`、`MAX_FAIL_KEEP`。

## 3. 推荐用法

以下均在板子上、已是 root、当前目录有 `rs485-test`。PC 侧用任意串口工具连同一条 RS485（A/B 极性一致、共地）。

### 3.1 只听对端（连通性）

```bash
./rs485-test recv
```

对端发几个字节，板上应出现 `[RX]` 行。Ctrl-C 退出，GPIO 会回到接收。

后台：

```bash
MODE=recv ./start.sh
tail -f /tmp/rs485-test.log
./stop.sh
```

### 3.2 板上回显，PC 发什么收回什么

```bash
./rs485-test echo
```

或：

```bash
MODE=echo ./start.sh
```

确认半双工时序：回发前会先切 TX，再切回 RX。两端不要同时主动发。

### 3.3 短帧倒序测试（首帧缓存）

对端反复发同一段 **1～8 字节** 时用这个模式。只对启动后第一帧做倒序，之后只比对是否相同，相同则直接回缓存，尽量快。

```bash
./rs485-test reverse
# 等价
./rs485-test test
```

或：

```bash
MODE=reverse ./start.sh
```

对端发 `01 02 03 04`，板上回 `04 03 02 01`。后续同样内容不再重新倒序。内容不同则不回发、不改缓存。超过 6 秒没收到任何数据，会把缓存倒序再发一次（静默持续则每 6 秒一次）。

本模式不等待 `--frame-idle-ms`：读到数据后立刻抽干内核已到字节（最多 8）并回发。

### 3.4 交互对发

```bash
./rs485-test duplex
```

键盘输入一行回车即发送（程序会补 `\n`）。对端来的数据打印在终端。

管道发完后继续听（直到 Ctrl-C）：

```bash
printf 'hello\n' | ./rs485-test duplex
```

### 3.5 发一次就退 / 发完接着听

```bash
./rs485-test send 'hello'
./rs485-test send --file /tmp/payload.bin
./rs485-test send 'hello' --stay
```

脚本：

```bash
MODE=send SEND_TEXT='hello' ./start.sh
MODE=send SEND_TEXT='hello' STAY=1 ./start.sh
```

`send` 不能同时给文本和 `--file`。

### 3.6 压测与误码

发送端（板 A 或本板）：

```bash
./rs485-test traffic --count 1000 --payload 32 --interval-ms 20
```

`--count 0`（默认）一直发到 Ctrl-C。

接收端建议 quiet + crc：

```bash
./rs485-test -q --crc recv
```

脚本：

```bash
QUIET=1 CRC=1 MODE=recv ./start.sh
# 另一端：
MODE=traffic COUNT=1000 PAYLOAD=32 INTERVAL_MS=20 ./start.sh
```

测试帧格式见下文。对端若不是本程序 `traffic`，接收端的「非测试帧」会增加，CRC 通过数没有意义。

### 3.7 两板循环收发文件

两块 QCM6125 接同一条 RS485。先起接收端，再起发送端。不要两端同时 `file-send`。

```bash
# 板 B：不传 MD5，第一份收齐的文件记为基准并保留 first-xfer*
./rs485-test -q file-recv --dir /tmp/rs485-rx

# 板 A：按源文件计算 MD5 并循环发送
./rs485-test -q file-send --file /opt/payload.bin
```

需要事先钉死哈希：

```bash
./rs485-test -q file-recv --dir /tmp/rs485-rx --expect-md5 <32hex>
./rs485-test -q file-send --file /opt/payload.bin --md5 <32hex>
```

`--expect-md5` 一旦给出，第一轮也必须匹配，不再自动记录，通过也不留 `first-*`。失败样本名为 `fail-xfer{id}-got{md5前8位}.bin`，坏帧为 `fail-xfer{id}-bad.bin`，默认最多保留 16 个 `fail-*`（不删 `first-*`）。收齐后会 `fsync` 并用 `posix_fadvise(DONTNEED)` 丢掉该文件页缓存，再重新打开算 MD5。`--dir` 应落在真实块设备上；`/tmp` 若是 tmpfs，剔除页缓存可能无效。

后台：

```bash
MODE=file-recv DIR=/tmp/rs485-rx ./start.sh
MODE=file-send FILE=/opt/payload.bin COUNT=0 ./start.sh
```

115200 下大约 11 KB/s，1 MB 约 90 秒。参数说明见 [2.3](#23-file-send-参数)、[2.4](#24-file-recv-参数)。

## 4. start.sh / stop.sh 环境变量

`start.sh` 会 nohup 到后台，日志默认 `/tmp/rs485-test.log`，pid 优先 `/var/run/rs485-test.pid`，否则 `/tmp/rs485-test.pid`。

| 变量 | 默认 | 说明 |
|------|------|------|
| `DEVICE` | `/dev/ttyHS3` | 串口 |
| `GPIO` | `123` | 方向脚 |
| `BAUD` | `115200` | 波特率 |
| `FORMAT` | `N8N1` | 帧格式 |
| `MODE` | `duplex` | `duplex\|echo\|recv\|send\|traffic\|reverse\|file-send\|file-recv`（`test` 同 reverse） |
| `QUIET` | `0` | `1` 开启 `-q` |
| `CRC` | `0` | `1` 开启 `--crc` |
| `STATS_INTERVAL_MS` | 空 | 非空则传给程序 |
| `SEND_TEXT` | 空 | `MODE=send` 必填 |
| `STAY` | `0` | send 后继续 recv |
| `COUNT` | `0` | traffic 帧数或 file-send 轮数，0=无限 |
| `PAYLOAD` | `32` | traffic payload 字节 |
| `INTERVAL_MS` | `20` | traffic / file-send 帧间隔 |
| `FILE` | 空 | `MODE=file-send` 必填，源文件路径 |
| `MD5` | 空 | file-send 可选，32 位 hex |
| `CHUNK` | `1024` | file-send 分片字节 |
| `ACK_TIMEOUT_MS` | `15000` | file-send 等待 ACK |
| `DIR` | `/tmp/rs485-rx` | file-recv 落盘目录；要避开页缓存应指向真实分区，不要用 tmpfs |
| `EXPECT_MD5` | 空 | file-recv 可选基准 MD5 |
| `IDLE_TIMEOUT_MS` | `5000` | file-recv 收片空闲超时 |
| `MAX_FAIL_KEEP` | `16` | file-recv 最多保留 `fail-*` 失败样本，不删 `first-*` |
| `EXTRA_ARGS` | 空 | 追加到命令行（如 `--tx-setup-us 100`） |
| `LOG` | `/tmp/rs485-test.log` | 日志路径 |
| `PIDFILE` | 自动 | pid 文件 |

重复启动会报「已在运行」，先 `./stop.sh`。`stop.sh` 的 `GPIO` 应与启动时一致。

前台调试不要用 start.sh，直接跑二进制，方便看报错。

## 5. 日志怎么读

### 5.1 启动配置

```text
2026-09-18 17:00:00.123 cfg device=/dev/ttyHS3 baud=115200 format=N8N1 gpio=123 ...
2026-09-18 17:00:00.124 mode=recv  只接收。Ctrl-C 退出。
```

quiet 时不打印这些 info，仍会在退出时打汇总。

### 5.2 报文行

```text
2026-09-18 17:00:01.001 [RX] len=5 ascii="hi.." hex=68 69 0d 0a 00
```

`ascii` 里非 0x20–0x7e 显示为点。

### 5.3 统计行

```text
RX 100包 4200字节  TX 0包 0字节  UART帧错0 奇偶0 溢出0  UART错误率0.0000%  CRC通过100 失败0 丢包0 重复0 非测试帧0  帧错误率0.0000% 丢包率0.0000%
```

| 字段 | 含义 |
|------|------|
| RX/TX 包、字节 | 空闲组帧后的收发次数与字节 |
| UART 帧错/奇偶/溢出 | 打开串口后 `TIOCGICOUNT` 增量 |
| UART 错误率 | UART 错误计数 / RX 字节 |
| CRC 通过/失败 | 仅 `--crc` |
| 丢包 | 序号出现空洞（例如期望 3 却来了 5，记丢 2） |
| 重复 | 序号落后或同一序号再来 |
| 非测试帧 | 开头不是 `A5 5A` |
| 帧错误率 | CRC 失败 / (通过+失败) |
| 丢包率 | 丢包 / (丢包+CRC 通过) |
| `UART计数=不可用` | 该 tty 不支持 ioctl，不影响收发 |
| FILE通过/失败 | 仅 `file-send` / `file-recv`：发送端按 ACK，接收端按本地 MD5 |
| ACK超时 | 仅 file-send：本轮未等到匹配的 ACK |

分母为 0 时百分比为 `n/a`。

文件模式还会打（quiet 也打）：`出错 原因=… 继续收本轮`、`已记录基准 MD5=... 已保留 first-xfer*`、`通过 ... 已删除`、`失败 原因=… 已收片=… 已写=… 首处缺片=… 已保留 ...`。

## 6. 测试帧（traffic / --crc）

```text
A5 5A | seq u32 LE | len u16 LE | payload | CRC16-IBM LE
```

- CRC 覆盖 seq + len + payload（不含魔数）。
- 算法：CRC-16/IBM（ARC），反射多项式 `0xA001`，初值 0。
- traffic 的 payload 第 i 字节为 `(seq 低 8 位 + i) & 0xFF`。
- 一帧最大约 8192 字节（含 10 字节头尾）。

接收端必须加 `--crc` 才会拆帧统计。echo 回的是原始字节，不会改序号。

`file-send` / `file-recv` 把文件消息放在测试帧 payload 里：

```text
META  01 | xfer_id | file_size | chunk_count | md5[16] | name_len | name
DATA  02 | xfer_id | chunk_idx | data
ACK   03 | xfer_id | result | got_md5[16]
```

接收端按片号把实际收到的字节写入（不补 0，同一片只留第一次）。CRC 坏帧原文写入 `-bad.bin`。以落盘后剔除页缓存再回读的 MD5 为准，不盲信 META。未传 `--expect-md5` 时，第一份收齐的文件保留为 `first-xfer{id}.bin` 并记为进程内基准。第一份若已传坏，后续正确文件会被判失败。

## 7. 半双工注意点

1. **不要两端同时发**。典型安排：一侧 echo/reverse，一侧 send/traffic；或一侧 recv，一侧 traffic；**文件循环：一侧 file-send，一侧 file-recv**。
2. 发完必须等对端切回 RX。未指定 `--tx-setup-us` / `--tx-hold-us` 时按波特率自动算（setup=1 字节时间、hold=2 字节时间，均不低于 50 µs）。若对端回显偶发缺头字节，可加大这两个参数。
3. `--frame-idle-ms` 要大于对端字节间隔、小于你期望的「两帧间隙」。默认 30 ms 适合人工输入和 20 ms 以上的 traffic 间隔。`reverse` 不用该参数组帧。
4. 连续无间隙的字节会被拼成一帧，直到空闲或 8192 上限。
5. duplex 收发共用一把串口锁：正在收时，stdin 那一行会等到本帧读超时结束才发出。

## 8. 排障

| 现象 | 处理 |
|------|------|
| `需要 root` | `sudo` 或切 root |
| `打开串口 … 失败` | 查设备名、是否被占用、`fuser /dev/ttyHS3` |
| `export GPIO 失败` | 确认 sysfs GPIO、编号是否为 123、是否被别的进程占用 |
| 能发不能收 | 查 A/B 是否接反、对端是否也在发、本端 GPIO 是否卡在 0；`stop.sh` 后看 `gpio123/value` 应为 `1` |
| 能收不能发 | 示波器/逻辑分析看 GPIO 发送瞬间是否拉低；加大 `tx_setup_us` |
| 回显缺字节或 CRC 大量失败 | 加大 `tx_hold_us`；降低波特率对比；查终端电阻与共地 |
| 一包被拆成多行 RX | 增大 `--frame-idle-ms` |
| 多包粘成一行 | 减小 `--frame-idle-ms`，或对端帧间加间隔 |
| `UART计数=不可用` | 可忽略，改看 `--crc` 统计 |
| start 后立刻退出 | 看 `/tmp/rs485-test.log` |
| 编译下载工具链失败 | 手动把 tar.xz 放到脚本打印的 `tools/*.tar.xz` 路径后重跑 |

退出时 GPIO 会拉回 RX。若进程被 `kill -9`，请执行一次 `stop.sh` 或手动：

```bash
echo 1 > /sys/class/gpio/gpio123/value
```
